# 2026秋季Geek组 - 前期考核任务书


## 1️⃣阶段一 【Geek 的出厂设置 - `GitHub` 入门与 Markdown 学习】

### 阶段时长：`1.5` 天

### 🛒学习内容

1. 初步了解 `GitHub` 

2. 学习使用 Markdown

   > Markdown 可能是未来 Geek 们接触最多的工具，当你真正爱上它的时候，电脑中的 Word 似乎再也没怎么打开过......

### 📑任务内容

**❗❗❗注意：考核期所有笔记/文档须为 `.md` 格式，当前与此后的所有任务内容均上传至你在 `GitHub`创建的名为 Tasks 的仓库**

1. 用上你学的 Markdown 语法，组织一份整洁规范的文档，跟我们说说：
   - 你觉得什么是Geek，什么又是 Geek 精神？
   - GitHub 是干什么的？
     Pull Request、Fork 这些词你是怎么理解的，又是从哪里学到的？
   - 有学长当年光是打开 GitHub 网站就花了半天，你有过类似经历吗？
     不管有没有，说说你的判断。
   - 这份文档凭什么称得上整洁规范？你遵循了哪些规范？

2. 创建 Profile README 仓库，美化你的 GitHub 主页
   - **参考至少 2 个优秀的 GitHub Profile README(并给出对应的参考链接🔗)**      
   - 记录📝在你的学习笔记中记录你参考了哪些案例，学到了什么技巧

3. 整个学习过程中遇到过什么问题呢？新建一份**问题解决记录**，记录一下吧！

   > 可以下载 **问题解决记录模板**。

4. **[选做-进阶]** 了解 Markdown 的底层原理，探索一下你的编辑器还有什么奇妙或者方便的功能，写成文档分享给大家和未来的学弟学妹吧。

5. **[选做-进阶]**探索一下Markdown的局限，哪些笔记类型是Markdown不擅长的呢？你又找到了哪些软件来做这类笔记呢？（同样写入Markdown进阶笔记）

### 📑这阶段后，你的仓库里应该有

* **个人 Profile README 仓库**

* **GitHub 学习笔记**

* **Markdown 学习笔记**

* **Markdown 练习文档**

* **问题解决记录**

* **[可选] Markdown 进阶笔记**

  > 除以上内容外，我们也很希望看见你的其他思考——无论大或小，深或浅，无论有关什么

### 💕友情提示

1. [GitHub 指南](https://zhuanlan.zhihu.com/p/337959303)

2. 推荐阅读 [GitHub 官方指南](https://docs.github.com/zh/get-started)

   > 拥有一个自己的知识库体系多是一件妙事，不要等到"垃圾分类”时再感慨 —— 小江

3. 推荐使用 Markdown编辑器 **Typora**，要花点钱——当然，办法总比困难多

4. 多加练习，习惯使用

5. 学有余力的小伙伴可以进一步了解，[PARA 笔记整理法](https://www.playpcesor.com/2022/04/para.html#google_vignette)

6. Geek 的自由并不体现在笔记的 ”乱七八糟“ 风格上，
   希望大家可以思考 Markdown 中每个语法的应用场景，给自己的技术文档写作风格设定一套适合自己习惯的规范

   > 每年复盘调整下规范，越用越顺手

## 2️⃣阶段二 【Geek 的出厂设置 - `GitHub` 进阶与 **Git 学习**】

### **阶段时长：`2` 天**

### 🛒学习内容

1. 学习 Git 的基本流程（clone、add、commit、push 等），并尝试**使用 Git Bash 完成**基本操作

2. 学习如何与他人在`Github` 上协作完成项目

### 📑任务内容

❗❗❗注意：从这里开始，我们会逐渐接触更复杂的问题，如有疑问，希望你**适度**使用 AI 大模型，并及时与 mentor 交流！

1. 使用 Git Bash 提交并推送名为 `hello.md` 的文档到远程仓库，内容为 `# Hello + 你的姓名`，并在 Git 学习笔记中简单说明完整提交的流程。
2. 你认为使用 Git Bash 提交麻烦吗？找一找，有没有更方便、更有效率的提交方式？
3. 我们在当前仓库的 `main` 分支下留有一个名为 `git-idea` 的文件夹，你们可以将你们的 Git 学习感想(记得标注名字)放进来,并向我们提 PR。
4. 通过文件夹找各阶段的文件太繁琐了，既然已经学会了 Markdown，你就可以为你的仓库建立一个 README.md 索引，点击即可跳转。实现它！
5. 在学习过程中遇到的问题、报错等，可以写进**问题解决记录**，养成记录问题的好习惯。
6. **[选做-进阶]** 如果提交错了怎么办？——了解一下版本回滚和冲突解决。这会让你收获很多！

### 📑这阶段后，你的仓库里应该有

* **Git 学习笔记**
* **Git 提交练习文档 (hello.md)**
* **问题解决记录**
* **[可选] Git 进阶笔记**
* ***Your other thoughts**

## 3️⃣阶段三 【 Web 相关领域的基础 - HTML / CSS / JavaScript 】

### 阶段时长：`10` 天

### 🛒学习内容

❗❗❗**注意：本阶段的各个学习内容存在强联动，不建议单独学习，建议分别进行基础语法了解后联动学习。重点学习 HTML 与 CSS 。**

1. 学习 HTML 与 CSS 基础，了解 JS，并综合应用
2. 学会用 `GitHub Pages` 部署静态页面

### 📑任务目标

1. 👉使用 HTML、CSS 与 JS 制作**一个属于你自己的静态网页**，展示任何你想展示的内容，然后使用`Github Pages` 部署该页面。👈

   - **致如此努力的你**： 

     坚持到现在的你非常棒！
     而本项目将是你第一个完整实现的前端项目，或许有许多 BUG、障碍挡路，
     但我们希望你用心思考，多多实践、终能披荆斩棘，用一行行代码展示出你最耀眼的光辉。

   - **我们鼓励创新，但请力所能及**：

     如学有余力，可以添加独属于你的创新亮点，
     但我们不希望直接借助 AI 实现本不属于你的东西，
     也不希望你为了创新而忽视了基本。


   - **我们允许简单，只要你尽力**：

     如果你确实时间较少或者学习相对吃力，
     可以只用 HTML、CSS 与 JS 的一两种制作一个简单的页面demo，
     尽力而为并持续学习，一定会成为优秀的人。

2. 无论你的项目如何，详细编写一篇 “编后感” ，说说：
   - 你构想了一个什么项目，
     最终完全实现你的构想了吗？
   - 你在项目中，是如何用 HTML 给它搭建骨骼、用 CSS 给它增添颜值、用JS给它赋予变化的？
   - 我们总是在关关难过关关过中成长，
     说说你在项目中遇到的最大难题是啥？你又是如何克服和解决的？
   - 你认为当前的项目还需要优化和补完吗？
     如果将来你成为一方 dalao，你会想回到最初为这个项目填上最后一块砖吗？
