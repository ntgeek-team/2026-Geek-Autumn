# Git 学习感想 frozen
这段时间学习 Git、GitHub 和 Markdown，上手之后才发现，看着简单，实际操作的时候坑特别多，一路摸索下来收获很多，当然也走了不少弯路，花费不少力气。

刚开始面对任务的专有名词看都看不懂，分不清 Git、Git Bash 和 GitHub 到底有什么不一样。一开始配置 SSH 反复报错，网页时不时加载失败，折腾很久；还要研究个人主页 Profile 怎么设置才能正常展示，经常对着任务要求看很久，理解不到位，不知道下一步该点哪里，常常卡住。很多名词像 fork、pull request、push 看着就头疼，只能一点点查、一点点试。

在不断实操练习的过程里，我慢慢熟悉了整套流程。我学会用 Git Bash 敲命令，先用 add 把修改的文件放到暂存区，再用 commit 保存这次改动，push 把文件上传到线上仓库，pull 同步别人更新好的内容。同时学会用 Markdown 写学习笔记，用标题、列表、引用整理知识点，排版清爽，比 Word 更适合记录技术内容。

这次任务我也弄懂了开源协作 Fork + PR 的模式。大白话来说，就是先把导师的仓库复制一份到自己账号，在自己的副本里面新增、修改文件。改完之后发起 PR，相当于提交申请，请导师审核我的内容。老师确认没问题，就可以把我的内容合并回原仓库。

动手操作之后我才体会到版本管理的好处，每一次提交都会留下记录，不怕改错之后找不回之前的内容。虽然基础流程已经跑通，但我也清楚自己还有很多薄弱的地方，比如版本回退、代码冲突怎么处理，这些还不太熟练。之后我打算多动手练习，巩固今天学到的协作流程，继续吃透 Git 的更多用法。
