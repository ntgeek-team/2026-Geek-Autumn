## 学习内容

### 一、对 Git 的初步理解

学之前我一直把 Git 和 GitHub 混为一谈，以为是一回事。学完才理清：Git 是装在自己电脑上的版本管理工具，断网也能用；GitHub 是托管 Git 仓库的网站，负责备份和协作。这个区分看着基础，但对我理解后面所有命令都很关键——比如 commit 是在本地生成一个版本，只有 push 之后才会传到 GitHub。

还有一个概念帮我理解了很多：**工作区 → 暂存区 → 版本库**。改文件是在工作区，git add 把改动放进暂存区，git commit 才把暂存区的内容打包成一个正式版本。搞懂这个之后，就明白了为什么不能直接 commit、为什么 add 之后还要 commit。

### 二、完整提交流程走下来的感受

第一次从头到尾走 clone → add → commit → push，最有成就感的时刻是 push 之后刷新 GitHub 网页，看到 hello.md 真的出现在远程仓库里——本地的一个文件，通过几条命令就同步到了网上，这个感觉很奇妙。

中间也踩了坑：第一次 commit 直接报错，提示没有配置 user.name 和 user.email。查了才知道 Git 要记录是谁提交的，得先用 git config 配置身份。还有一次 add 完忘了 commit 就想 push，结果什么都没传上去——这才理解 add 和 commit 是两步，add 只是放进暂存区，不 commit 就不会生成版本。

### 三、命令行 vs 图形化工具

一开始觉得敲命令挺麻烦的，参数记不住，敲错就报错。但走完一遍发现核心命令就那几条，add / commit / push / pull 来回用，熟练之后反而很快。

我也找了更省事的方式：VS Code 自带 Git 集成，写代码时侧边栏就能看到改动、暂存、提交，点几下完成；GitHub Desktop 是纯图形界面，对新手更友好。但组内提示说"避免过度依赖图形化操作"，所以我打算图形界面用来提效，命令行的基本功还是自己练扎实——毕竟报错的时候，最后还是得靠命令行解决。

### 四、对协作与 PR 的理解

阶段一我理解了 Fork 和 Clone 的区别，这次真正用上了：Fork 别人的仓库到自己账号，clone 到本地改完推上去，再发 PR 请求对方合并。这次把感想放进考核仓库的 git-idea 文件夹、提 PR，就是完整走了一遍这个协作流程。以前觉得 PR 是高手才用的东西，自己走一遍发现其实就是"我改好了，请 review 一下"这么回事。
