## 学习内容

### Git基础提交流程

如果在本地写文件上传到GitHub，需要三步：
1. `git add`：把文件加入暂存区
2. `git commit -m "备注信息"`：生成本地版本记录
3. `git push`：把改动上传到远程仓库

### 实操中遇到的问题与错误总结

1. 找不到Fork按钮
一开始在自己的仓库页面找Fork，一直找不到。
知识点：Fork是用来复制别人仓库的，自己的仓库没有Fork按钮。

2. 误以为网页修改会自动同步本地文件
在GitHub网页新增或者修改文件，本地电脑里的文件不会自动更新。想要把网页上最新内容拿到本地，需要执行 `git pull`。

3. 分不清push和pull的方向
- `git push`：本地的改动上传到GitHub远程网页
- `git pull`：把远程网页上的更新拉到本地电脑

4. Git命令对格式要求严格
命令里面的空格、字母不能写错，少空格、打错字母都会报错。

### Fork 和 PR

Fork：复制别人的仓库，生成一份属于自己的副本，这样我才有修改权限。
PR（Pull Request）：我在fork出来的副本修改完成之后，发起一个请求，交给原仓库的作者或者老师审核，审核通过后改动就合并进原仓库。像这次交作业，就需要走Fork+PR这个流程。

## 一些感想，或者想法

这次实操让我明白Git命令很严谨，一点点格式错误就会执行失败。本地仓库和远程仓库是分开的，不会自动同步。Fork加PR的方式可以保护原仓库，适合作业提交和多人协作。
